# Numerical regression testing

JETSPIN provides a numerical regression suite in
[`tests/regression/`](../../tests/regression/). It complements the smoke
tests: smoke tests detect crashes, invalid values, and inactive feature paths,
whereas regression tests detect unexpected changes in computed observables.

## Test matrix

The suite exercises all eight example models. For each case it performs:

1. a serial run compared with a versioned reference baseline;
2. a two-rank MPI run compared with the serial result generated by the same
   source and compiler configuration.

Each run executes exactly 1,000 integration steps while retaining the
original timestep from its example input. The final time is calculated as
`1000 * timestep`, and output is sampled every 200 steps. Each result
therefore contains the initial state and five subsequent samples.

The suite runs entirely in temporary directories. It does not modify the
example inputs or normal build products.

## Compared observables

The temporary inputs use a common `statout.dat` schema:

```text
t x y z vx vy vz st n rc curn curc nref
```

CPU timings and other machine-dependent diagnostics are deliberately
excluded. The comparison also includes the leading integration-step column
`nstep` written by JETSPIN.

Discrete fields are compared exactly:

- `nstep`, the integration-step number;
- `n`, the active bead count;
- `nref`, the number of completed refinement events.

Continuous values use the combined relative and absolute criterion:

```text
abs(actual - reference) <= atol + rtol * abs(reference)
```

This criterion remains meaningful both for large observables and for values
close to zero. A binary file comparison is not used because insignificant
floating-point differences may occur across processors and compilers.

## Default tolerances

| Comparison | Relative tolerance | Absolute tolerance |
| --- | ---: | ---: |
| Serial versus versioned baseline | `1e-7` | `1e-10` |
| Two-rank MPI versus matching serial run | `1e-6` | `1e-9` |

The MPI tolerance is slightly wider because collective reductions can change
floating-point summation order. These defaults are intended as portable
starting values, not permission to accept unexplained deviations.

Override them for diagnostic work with:

```sh
JETSPIN_REGRESSION_RTOL=1e-8 \
JETSPIN_REGRESSION_ATOL=1e-11 \
JETSPIN_MPI_REGRESSION_RTOL=1e-7 \
JETSPIN_MPI_REGRESSION_ATOL=1e-10 \
tests/regression/run.sh
```

## Distributed stochastic coverage

The original short examples generally contain too few beads to distribute
work across two MPI ranks because JETSPIN uses a minimum chunk size of ten.
Merely launching two processes would therefore leave the second process idle
and would not test rank-independent random-number assignment.

The regression copy of Test Case 4 is consequently initialized with:

```text
points 25
initial length 0.2d0
```

The longer initial jet keeps the discretization valid with 25 beads. On two
ranks, the active beads are split 13/12, so both ranks execute stochastic
Platen work. The example file in `examples/input-4/` remains unchanged.

Rank 0 generates globally indexed Gaussian blocks and broadcasts them before
distributed integration. The regression comparison verifies that this
stochastic trajectory matches the serial trajectory. See
[random numbers and MPI reproducibility](random-numbers.md) for the runtime
design.

## Running the suite

On a system where the default `mpif90` and `mpirun` select a matching
GFortran/OpenMPI installation, run:

```sh
tests/regression/run.sh
```

When several MPI installations are available, select the wrappers explicitly:

```sh
JETSPIN_MPIFC=/path/to/mpif90 \
MPIEXEC=/path/to/mpirun \
tests/regression/run.sh
```

On the currently documented local module environment, an equivalent setup is
to load `mpi/openmpi-x86_64` before running the suite.

To retain temporary inputs, logs, executables, and output for diagnosis:

```sh
JETSPIN_REGRESSION_KEEP=1 tests/regression/run.sh
```

The default timeout is 30 seconds per simulation. Override it with
`JETSPIN_REGRESSION_TIMEOUT`.

## Running selected cases

An inclusive case interval can be selected without changing the script:

```sh
JETSPIN_REGRESSION_FIRST_CASE=4 \
JETSPIN_REGRESSION_LAST_CASE=4 \
tests/regression/run.sh
```

This is useful while investigating one model. The normal pre-merge check must
still run the complete `1..8` matrix.

## Versioned baselines

Serial reference results are stored under
[`tests/regression/baselines/`](../../tests/regression/baselines/). Generate
new baselines only after an intentional and scientifically understood
numerical change:

```sh
tests/regression/run.sh update
```

Updating a baseline is not a repair for a failing test. Review changes in
every affected observable, record why the numerical result changed, rerun the
normal check mode, and include the baseline update in the same commit as the
model or algorithm change that requires it.

## Interpreting failures

A failure should first be classified as one of these categories:

- exact topology mismatch in `n` or `nref`;
- output-shape or sampling mismatch;
- serial result outside its baseline tolerance;
- MPI result outside its matching serial tolerance;
- non-finite or malformed numerical output;
- build, timeout, or MPI-launch failure.

Do not immediately widen tolerances. Preserve the temporary directory,
identify the first row and observable that diverges, and determine whether
the cause is an intended model change, floating-point ordering, stochastic
assignment, topology evolution, or a defect.

## Relationship with smoke tests

The recommended numerical pre-merge validation is:

```sh
tests/smoke/run.sh serial
tests/smoke/run.sh debug
tests/smoke/run.sh mpi
tests/regression/run.sh
```

The runtime-checking smoke build remains important because numerical agreement
alone cannot detect every bounds, allocation, or undefined-behaviour error.
