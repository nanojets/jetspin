\section{Input file\label{sec:Input-file}}

In order to run JETSPIN simulations an input file has to be prepared,
which is a free-format and case-insensitive. The input file has to
be named \texttt{input.dat}, and it contains the selection of the
model system, integration scheme directives, specification of various
parameters for the model, and output directives. The input file does
not requires a specific order of key directives, and it is read by
the input parsing module. Every line is treated as a command sentence
(record). Records beginning with the symbol \# (commented) and blank
lines are not processed, and may be added to aid readability. Each
record is read in words (directives and additional keywords and numbers),
which are recognized as such by separation by one or more space characters.

The parser (subroutine \texttt{read\_input} in \texttt{io\_mod.f90}, with the
string utilities of \texttt{parse\_mod.f90}) follows a few simple rules that
the user should keep in mind. Each record is read up to 150 characters,
stripped of leading blanks and converted to lower case; records beginning
with \# or ! are skipped. A keyword is recognized when it matches the
beginning of any word of the record, and the top-level directives are tested
in a fixed order, the first match being accepted. Hence abbreviated forms are
equivalent (e.g. \texttt{dynam refin every} and
\texttt{dynamic refinement every}), but an invented keyword may silently match
another directive: \texttt{timesteps 15000} would be read as
\texttt{timestep 15000}. A numeric value is the first number found in the
record, scanning from the left, and directives expecting several values take
the following numbers in order. There are no end-of-line comments: comments
should be placed on separate records beginning with \#. An unknown directive
stops the program with an error banner (\texttt{ERROR - unknown directive
in input file}), as does the end of the file before the \texttt{finish}
record; records after \texttt{finish} are ignored. For most directives an
unknown sub-keyword prints warning 61, and the program stops after reading
the input file (\texttt{ERROR - incomplete input file}); \texttt{primary},
\texttt{maximum}, \texttt{multiple}, \texttt{restart}, \texttt{dragvel},
\texttt{evaporation}, and \texttt{dynam} without \texttt{refin} ignore it
silently instead, and \texttt{external potential} \textit{word} $f$,
\texttt{print xyz} \textit{word} $f$ and \texttt{print binary} \textit{word}
$f$ are read as \texttt{external potential} $f$, \texttt{print xyz} $f$ and
\texttt{print binary} $f$ (e.g. \texttt{print xyz rescale 1000} writes
\texttt{traj.xyz} every 1000 s). An unknown key in \texttt{print list} or
\texttt{printstat list} gives warning 48 or 58, followed by warning 60 with
the list of the valid keys, and the program stops after reading the input
file.

As in the example input files \textit{examples/input-N/input.dat}
described in the chapter of the example simulations, the last record is
a \texttt{finish} directive, which marks the end of the input data.
Before the \texttt{finish} directive, a wide list of directives may
be inserted (see Tab \ref{tab:inputlist}). The directive \texttt{system}
should be used to set the nanofiber model. In JETSPIN two models are
available: 1) the one dimensional model similar to the model of
Chapter~\ref{chap:JETSPIN-Model-and} but assuming the nanofiber to be straight
along the $\vec{\textbf{x}}$ axis, and, therefore, neglecting the
surface tension force $\vec{\textbf{f}}_{st}$; 2) the three dimensional
model described in Chapter~\ref{chap:JETSPIN-Model-and}. Internally these
options are handled by the integer variable \texttt{systype}, which
assumes the values explained in Tab \ref{tab:inputlist}. Further
details of the 1-D model can be found in Refs \cite{pontrelli2014electrospinning,carroll2011discretized}.
A series of variables are mandatory and have to be defined. For example,
\texttt{timestep}, \texttt{final time}, \texttt{initial length}, etc.
(see underlined directives in Tab \ref{tab:inputlist}). A missed
definition of any mandatory variable will call an error banner on
the terminal. The user can use two possible ways to define the initial
geometry of a nanofiber both given the mandatory directive \texttt{initial
length}: 1) the discretization step length of nanofiber is specified
by the directive \texttt{resolution}, which causes automatically the
setting of the jet segments number (the number of segment in which
the jet is discretised); 2) the jet segments number is declared by
the directive \texttt{points}, while the value of the discretization
step length is automatically set by the program (as in Example \textbf{Test
Case 3} in Sec \ref{sec:Test-Case-3:}). Exactly one of the two directives
must be given (warning 7 if neither is present, warning 22 if both are),
and the resulting step length must not be smaller than the \texttt{nozzle
cross} radius (warning 62, error 8). A few other values are checked when
the input is read: the \texttt{elastic modulus} must be at least
$10^{-4}$ (warning 88), the \texttt{initial length} must not be smaller
than the \texttt{nozzle cross} radius (warnings 42--44), and the
\texttt{perturb ampl} must not exceed the \texttt{initial length}
(warnings 45--47). The values of \texttt{system} and \texttt{integrator}
are not range-checked at input: an unsupported value, or combination
(e.g. \texttt{integrator 4} with \texttt{kvfluid yes}), stops the run at
the first step with \texttt{ERROR - ftype is wrong!} or \texttt{ERROR -
ktype error.}, respectively. The directive \texttt{primary
cutoff} sets a distance in centimeters. With \texttt{multiple step yes}
it is the radius of the neighbor list of the multiple timestep algorithm
for the Coulomb forces (Sec \ref{sec:Multiple-Timestep-Algorithm}), and it
is mandatory; every direct Coulomb sum used by the algorithm is then
complete. Without that algorithm it only truncates the direct Coulomb sum
of the one dimensional model (\texttt{system 1}), skipping the pairs
farther apart than the cutoff (and the image terms of the developer-only
\texttt{mirror} option); the three dimensional direct sum ignores
it. If it is omitted, no cutoff is applied. (Up to version 1.22 the
cutoff was converted from centimeters only with the multiple timestep
algorithm, and it truncated the one dimensional direct sum also under
that algorithm, which corrupted the extrapolation.)
The directive \texttt{restart yes} can be used to restart a JETSPIN
job (for further information see Section \ref{sec:Restarting-JETSPIN}).

The user should pay special attention in choosing the time integration
step given by the directive \texttt{timestep}, whose detailed considerations
are provided in Ref \cite{lauricella2015jetspin}. The reader is referred
to Tab \ref{tab:inputlist} for a complete listing of all directives
defining the electrospinning setup parameters. Not all these quantities
are mandatory: an omitted optional quantity is zero, or the feature is
off, unless Tab \ref{tab:inputlist} gives another default. Several
directives become mandatory once a feature is activated, as stated in the
table; if one of them is missing, the program prints a warning and stops
after reading the input file (\texttt{ERROR - incomplete input file}).
\textbf{Note all the quantities
have to be expressed in centimeter\textendash gram\textendash second
unit system} (e.g. charge in statcoulomb, electric potential in statvolt,
etc.).

The optional \texttt{job time} and \texttt{close time} directives
ensure a controlled close down procedure when a job runs out of
time. The time specified by the job time directive indicates the total
time allowed for the job, in seconds, or in minutes, hours or days when
followed by \texttt{m}, \texttt{h} or \texttt{d}; \texttt{job time indef},
like an omitted directive, sets no limit. The unit is best written as a
separate word (\texttt{job time 12 h}): a \texttt{d} attached to the
number is read as the exponent mark of a double-precision number, so that
\texttt{job time 2d} means 2 seconds. (It should be set equal to the
time specified to the operating system when the job is submitted.)
The \texttt{close time} directive represents the time JETSPIN will
require to write and close all the data files at the end of processing
(default: 0).
This means the effective processing time limit is equal to the job
time minus the close time: once it is reached, at the end of a time
step, the integration loop stops, the output files are closed and
\texttt{save.dat} is written as at the final time (no extra statistics
record is forced: the last record is that of the last multiple of
\texttt{print time}). The elapsed time is the wall-clock time since the
program started, as a batch system counts it (up to version 1.22 it was
the processor time of rank zero, which does not count waits and could
fall behind the batch limit).

A few directives are read only by developer builds, in which the logical
parameter \texttt{ldevelopers} of \texttt{nanojet\_mod.f90} is set to
\texttt{.true.} (it is \texttt{.false.} in released builds), and they are
not listed in Tab \ref{tab:inputlist}: \texttt{lorentz},
\texttt{magnetic field}, \texttt{variable mass}, \texttt{wall},
\texttt{mirror}, \texttt{breakup}, \texttt{ultimate strength},
\texttt{print pdb tagbead}, and the \texttt{type} option of
\texttt{dragvel yes}. A released build stops at the first seven with
\texttt{ERROR - unknown directive in input file}, gives warning 61 at
\texttt{print pdb tagbead} and stops after reading the input file
(\texttt{ERROR - incomplete input file}), and reads
\texttt{dragvel yes type} $i$ as \texttt{dragvel yes}.
