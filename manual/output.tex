\section{Output files\label{sec:Output-files}}

A series of specific directives causes the writing of output files
(see Tab \ref{tab:inputlist}). In JETSPIN five kinds of output files can
be written: 1) the file \texttt{statout.dat} containing time-dependent
statistical data of simulated process; 2) the file \texttt{traj.xyz}
reporting the nanofiber trajectory in XYZ format file; 3) the files
\texttt{frame\%06d.xyz} reporting the nanofiber geometries in splitted
XYZ format files (a single file for each frame); 4) the files \texttt{frame\%06d.pdb}
reporting the nanofiber geometries in splitted PDB (Protein Data Bank)
format files (a single file for each frame). Note that in the last
case a topological file \texttt{frame\%06d.psf} in PSF (Protein Structure
File) format will be printed alongside each pdb file. These two files
(PDB and PSF) can be opened by VMD-Visual Molecular Dyanamics \cite{humphrey1996vmd};
5) the binary restart file \texttt{save.dat}, written every
\texttt{restart dump} steps and at the end of the run (Sec
\ref{sec:Restarting-JETSPIN}). The developer binaries \texttt{traj.dat},
\texttt{bead.dat} and \texttt{statdat.dat} are written only with the
directives \texttt{print binary}, \texttt{print binary removed} and
\texttt{printstat binary} (see Tab \ref{tab:inputlist}). With the
environment variable \texttt{JETSPIN\_TOPOLOGY\_SNAPSHOT=1}, the text
file \texttt{topology-state.dat} records, at every insertion or removal,
a line \texttt{event} \textit{step inpjet npjet active add} followed by
one row per active bead (in reduced units). A restarted run appends
to \texttt{statout.dat} (after a new three-line header block),
\texttt{traj.xyz}, \texttt{statdat.dat}, \texttt{traj.dat} and
\texttt{bead.dat}, creating them if they are missing.

Various statistical data can be written on the text file \texttt{statout.dat},
and the user can select them in input using the directive \texttt{printstat
list} followed by appropriate symbolic strings, whose the list with
corresponding meanings is reported in Tab \ref{tab:outputlist}. The
selected observables will be printed at time interval on the same
line following the order specified in input file, preceded by the
integration-step number: each record is the step (format \texttt{i10})
followed by one column per key (format \texttt{g20.10}). A three-line
header beginning with \# names the columns at the top of the file (and
again where a restarted run starts appending); on the terminal it is
repeated every 100 records. In a new run the first record is written
before the first integration step (step 0), then one every
\texttt{print time}. (The file
\texttt{statdat.dat} is a different,
developer-only binary dump of all observables, written only with the
directive \texttt{printstat binary}.) In the same way,
a list of statistical data can be printed on computer terminal using
the directive \texttt{print list} followed by the symbolic strings
of Tab \ref{tab:outputlist}.

At normal termination, the terminal also reports the wall-clock duration of
the temporal integration loop and its throughput in integration steps per
second. The timer starts immediately before the loop and stops immediately
after it; input parsing, initial allocation, restart loading, and output-file
setup are therefore excluded. Integration, bead insertion and removal,
statistics, and scheduled output executed inside the loop are included. In
MPI builds, ranks are synchronized at both boundaries and rank zero reports
the elapsed duration of the slowest participating rank. This loop-only wall
time is the recommended measurement for CPU, MPI, and accelerator performance
comparisons. The throughput counts the steps of the current run only (after
a restart, the steps made before it are excluded).

Besides the records of \texttt{print list}, rank zero prints a few log
lines on the terminal (the complete list is in
\texttt{docs/data/output.md}):
\texttt{Gaussian history pool: values=}\textit{V} \texttt{covers}
\textit{S} \texttt{steps at} \textit{N} \texttt{beads} before the loop of a run that reads the pre-generated
Gaussian pool (Sec \ref{sec:Noise-pool}); in OpenACC builds,
\texttt{OpenACC device step engaged (}\textit{scheme, model}\texttt{) at
step} \textit{N} \texttt{with} \textit{M} \texttt{active beads} when the
device step engages (\texttt{resumed} instead of \texttt{engaged} after a
restart of an engaged run); \texttt{Topology event: step=}\textit{N}
\texttt{add=}\textit{T/F} \texttt{remove=}\textit{R}
\texttt{active=}\textit{M} at every step with an insertion or a removal;
\texttt{Dynamic refinement event: ...}, followed by diagnostic lines, at
every accepted refinement; at the end of the run, the totals
\texttt{Topology additions}, \texttt{Topology removals} and
\texttt{Array reallocations} (which include the steps made before a
restart) and the final \texttt{Topology active beads}, then \texttt{Program closed
correctly} and \texttt{CPU time = }\textit{T} \texttt{seconds on}
\textit{N} \texttt{CPU(s)}, where \textit{T} is the processor time of rank
zero since the program started (not the wall-clock time) and \textit{N}
the number of MPI ranks.

For performance diagnosis, setting the environment variable
\texttt{JETSPIN\_PROFILE=1} prints an optional wall-clock breakdown for the
integrator, Coulomb calculation, bead topology operations, breakup check,
statistics, scheduled output, and restart output. Profiling is disabled by default. The
Coulomb value is a nested part of the integrator total and must not be added
to it when interpreting percentages. The profiler prints cumulative wall
time, percentage of the complete temporal-loop time, and call count on the
terminal; it does not write a profiling file. These are explicitly
instrumented regions rather than an automatic measurement of every Fortran
subroutine. Region timings are inclusive, so the integrator value includes
the Coulomb, equation-of-motion evaluation, and Runge--Kutta update regions.

In MPI execution, the detailed region breakdown is local to rank zero and is
not reduced to the maximum over all ranks. The synchronized complete-loop
wall time should be used for MPI scaling. Since clock reads add a small
overhead, performance comparisons should enable profiling in both runs or
disable it in both runs.

The file \texttt{traj.xyz} is written as a continuous series of XYZ
format frames taken at time interval, so that can be read by suitable
visualization programs (e.g. VMD-Visual Molecular Dynamics \cite{humphrey1996vmd},
UCSF Chimera \cite{pettersen2004ucsf}, etc.) to generate animations.
The number of elements contained in the file is kept constant equal
to the value specified by the directive \texttt{print xyz maxnum},
since few programs (e.g. VMD) do not manage a variable number of elements
along the simulations. If the actual number of beads is lower than
the given constant \texttt{maxnum}, the extra elements are printed
in the origin point. On the other hand, the number of beads printed
in the files \texttt{frame\%06d.xyz} and \texttt{frame\%06d.pdb} is
exactly the actual number of beads used to discretized the jet at
the given frame. Note that the unit of mesurement used in the files
\texttt{traj.xyz} and \texttt{frame\%06d.xyz}, and in the files
\texttt{frame\%06d.pdb}, is the centimeter multiplied by $f$, which was given in input file
by the directive `` \textit{print xyz rescalexyz} $f$ '' and `` \textit{print
pdb rescalepdb} $f$ '' (see Table \ref{tab:inputlist}), respectively
(default: $f=1$, i.e. centimeters). In versions up to 1.22,
\texttt{traj.xyz} was written in reduced (internal) length units unless
\textit{rescalexyz} was given, and the frame files applied the length
unit twice when a rescale factor was given. The frame files are numbered
by the step divided by the frame interval, so that the first frame of a
new run is \texttt{frame000001} (a restarted run continues the
numbering). Since the coordinates are written with the
Fortran formats \texttt{f10.5} (XYZ) and \texttt{f8.2} (PDB), a rescale
factor may be needed to resolve a thin jet, or to keep large coordinates
within the field width.
