\section{Dynamic refinement\label{sec:Dynamic-refinement}}

In the original Ren model, each bead represent a constant quantity
$V_{c}$ of jet volume, so that the relationship $\pi a_{i}^{2}\,l_{i}=\pi a_{0}^{2}l_{step}=V_{c}$
is valid for any $i-th$ bead. Despite such relationship can be sometimes
a useful advantage (as example, see Sec \ref{subsec:Introduction-of-dimensionless}),
the radius reduction $a_{i}$ of the electrospun nanofiber provides
a significant increase of the discretization length $l_{i}$ value
along the jet path (also greater than two order of magnitude). As
consequence, it was observed in literature \cite{kowalewski2009modeling}
that the jet discretization close the collector becomes rather coarse
to model efficiently the nanofiber. To get around this problem the
dynamic refinement procedure developed in Ref \cite{lauricella2016refinement}
can be used in JETSPIN in order to maintain the the length of the
elements $l_{i}$ below a prescribed characteristic length max $l_{max}$.
Whenever a bead length $l_{i}$ is larger than $l_{max}$, the relevant portion
of the nanofiber is remeshed so that the target element length is no larger
than the value specified by \texttt{dynam refin threshold}. The base
insertion spacing $l_{step}$ does not define the refined mesh. The
discretization is performed by Akima
spline interpolations \cite{akima1970new,akima1991method} of the
main quantities describing the jet beads (positions, fiber radius,
stress, velocities). In order to perform the interpolation we proceed
following three steps. First of all, we introduce the variable $\lambda\in[0,1]$
to parametrize the jet path, where $\lambda=0$ identifies the nozzle,
and $\lambda=1$ the jet at the collector. For each bead we compute
its respective $\lambda_{i}$ value by using the formula

\begin{equation}
\lambda_{i}=\frac{1}{l_{path}}\sum_{k=1}^{i}l_{k}
\end{equation}
where $l_{path}=\sum_{k=1}^{N_{beads}}l_{k}$ is the jet path length
from the nozzle to the collector, and $i=1$ and $i=N_{beads}$ denote
the jet bead at the nozzle and collector, respectively ($i=0$ denotes
the nozzle). The set of ${\lambda_{i}}$ values represent the mesh
used to build the cubic spline. Given a generic quantity $y$, the
data $y_{i}=y\left(\lambda_{i}\right)$ are tabulated and used in
order to compute the coefficients of the \textit{Akima spline}, following
the algorithm reported in Ref \cite{akima1991method}. Then, we enforce
a target parametrization of the nanofiber. Without interior anchors, the new
mesh ${\lambda_{i}^{*}}$ can be represented schematically as

\begin{equation}
\lambda_{0}^{*}=0\;\lambda_{i}^{*}=\frac{i}{N_{beads}^{*}},\;i=1,2,\ldots,N_{beads}^{*}\text{.}
\end{equation}
where $N_{beads}^{*}$ is chosen from the path length and the configured
refinement threshold. In the implemented algorithm, each anchored segment of
arc length $L_s$ receives $\left\lceil L_s/l_{max}\right\rceil$ intervals.
Finally, the new values $y\left(\lambda_{i}^{*}\right)$
are computed for any $i-th$ bead by the \textit{spline interpolation}.
The procedure is repeated for positions, fiber radius, stress and
velocities of the jet beads in order to provide the respective quantities
in the new mesh ${\lambda_{i}^{*}}$. It is worth to dressing that
the volume $V_{i}=\pi a_{i}^{2}\,l_{i}$ represented by each bead
is not anymore constant, and, consequently, $\pi a_{i}^{2}\,l_{i}\neq\pi a_{0}^{2}l_{step}$.
It is also possible to keep selected beads in their positions before and after
the refinement procedure in order to reduce possible errors introduced
by the interpolation procedure. In other words, these anchor beads
are maintained as knots of both the old and new meshes (see directive
\texttt{dynam refin anchor} in Tab \ref{tab:inputlist}). If that spacing is
omitted it defaults to five times the discretization resolution; an
explicit value set below one resolution is likewise raised to that same
$5\times$ floor. In the
one-bead startup they are tagged as material is inserted. For a pre-extended
initial jet, interior anchors are initialized at the requested spacing before
the first timestep. The path endpoints are already common to both meshes and
are not tagged as interior anchors. An anchor is an ordinary material bead and
does not imply nanoparticle mass unless the separate variable-mass model is
enabled. Its role is to provide a persistent interpolation knot; it is not
spatially frozen during time integration. In the following text we will refer
to this emended version of the Ren model
as DyRen model. Further details on the implemented dynamic refinement
procedure are available in Ref \cite{lauricella2016refinement}.

For the serial Maxwell/Platen OpenACC path exercised by Test Case 21, the
time integrator, Gaussian history, insertion logic, and bead state remain in a
persistent device data region. After the configured minimum interval, a
device reduction returns only the last segment exceeding the threshold, the
total path length, and the nozzle correction used by the mesh-size test. No
bead array is transferred during an ordinary check. When a denser mesh is
actually possible, the active topology and evaporation state are downloaded
once. The host computes the normalized source and target coordinates. The GPU
then computes the interval slopes, Akima tangents, cubic coefficients, and all
field interpolations. Slopes, interior tangents, coefficient sets, and target
knots are independent parallel work; only the constant-size endpoint-slope
extrapolation is serial. The interpolated cross-section radius then drives a
second device kernel that reconstructs bead volume and evaporation volume,
rescales each for reference-volume conservation, and converts the
interpolated mass/charge densities back to per-bead quantities. The host
retains only the data-dependent, rare bookkeeping that these device kernels
build on and consume: the normalized target-mesh construction and anchor
save/restore/final-assembly rules, after
which the completed mesh is uploaded once and device integration resumes. The
normal Test 21 mesh reserves one allocation increment. A capacity-growth
validation reduces that reserve and forces the accepted mesh beyond the old
bound. In this case the topology and evaporation mappings are released before
the host arrays are replaced; the Platen and Coulomb workspaces are resized,
the Gaussian history is repacked for the new bead stride, and the completed
state is bound once. Existing Gaussian values are retained and values for new
indices are generated only during this event.

This allocation increment is the \uline{dynam refin capacity} $i$ input
directive (default 100 beads if omitted; the value must be positive). It sets
both the headroom reserved for a pre-extended anchored jet and the growth
increment applied whenever an accepted refinement event exceeds the current
capacity.

Test Case 22 exercises this event lifecycle three times. Developer-only
20-entry reserve and growth overrides force three successive capacity
increases, while the normal production increment remains 100. Each event
preserves every active anchor and separately conserves reference volume,
evaporated volume, mass, and charge. This repeated test verifies the mapping
lifecycle together with the device Akima spline.

Test Case 23 adds collector removal to the same lifecycle. Removal advances
the active lower bound and clears the collected bead through the device
topology primitive; it does not download the full jet. The validation requires
removal both before and after the third Akima event, so repeated device
interpolation and capacity replacement are checked with a rebased active
interval. Complete intermediate state transfers remain confined to accepted
refinement events.

Its CPU/GPU statistics agree within tolerance for all but the last two rows;
once the jet reaches the collector the two builds accumulate a different
number of collector removals (ten on the CPU, four on the GPU) because
direct-Coulomb summation order is amplified by the stochastic bending
trajectory near the collector. Isolating only the direct Coulomb sum on the
host while keeping topology and the reconstruction kernel below on the device
confirms this: the isolated build's third event and first seven removals then
match the CPU step-for-step, and only the last statistics row still
diverges. Matching topology, conservation, and this tolerance -- not
bit-for-bit trajectory identity -- remain the acceptance criteria for this
test.

A development host-Akima target retains the historical coefficient and
interpolation routines as an oracle. A second comparison target executes both
paths for each field. Across the 11 fields and three Test Case 23 events, the
largest coefficient relative difference is $2.48\times10^{-15}$; interpolated
values differ by at most $7.28\times10^{-12}$ absolutely and
$3.32\times10^{-15}$ relatively.

A third development target applies the same host-then-device oracle pattern
to the volume-reconstruction/conservation/density kernel: it backs up the
pre-reconstruction state, evaluates the trusted host reference, restores that
state, then runs the device kernel so it remains authoritative, and compares.
All three Test Case 23 events agree with the host reference at or near
roundoff (worst absolute $7.1\times10^{-15}$, worst relative
$4.05\times10^{-16}$). Building this oracle exposed two ordering mistakes
before they reached the standard path -- the device kernel invoked twice, and
the host reference evaluated from already-converted state -- each of which
corrupted the event's mass/charge invariant by tens of percent, which is why
every new device stage in this port is validated with such an A/B comparison
before being trusted.

\subsection{Numerical robustness of the cross-section reconstruction\label{subsec:Refinement-robustness}}

A long production run growing from a single nozzle bead through several
dozen consecutive accepted refinement events (an untracked development case
combining the Test 23 physics with a much longer integration window) exposed
two distinct numerical weaknesses of the reconstruction described above,
neither of which is visible in the short Test 21--23 validation windows.

The first concerns the evaporated-volume floor. Every ordinary per-timestep
integrator already enforces $\bar V_{i}/\bar V_{i}^{0}\geq\text{evlim}$
(Sec.~\ref{sec:Evaporation}), but the accepted-event reconstruction of
$\bar V_{i}$ from the interpolated evaporation radius did not. An Akima
undershoot on that field could leave the ratio far below evlim -- observed
directly, to about one seventh of it, uniformly across nearly the whole
active jet in a single event -- inflating the polymer mass fraction $c_{p}$
well past unity and driving the Maxwell evaporative stress equation toward
overflow. The floor is now restored by a water-filling redistribution after
the existing conservation rescale: beads below their own floor are clamped
up to it, and the resulting deficit is taken from the still-compliant beads
in proportion to their surplus, iterated in case that step creates a new
violator, so that the segment's evaporated-volume total is preserved to
roundoff rather than broken, as a naive clamp alone was found to do. If the
floor is mathematically incompatible with the segment total, the event is
aborted rather than silently violating either constraint.

The second weakness is independent of evaporation and reproduces with it
disabled: the cross-section radius $a_{i}$ (fit independently by Akima and
then squared into $V_{i}=\pi a_{i}^{2}l_{i}$, and through the bead density
into its mass) can compound a nonphysical thinning across \emph{successive}
accepted events -- each one re-fitting from the previous event's own
output -- well beyond the order-of-magnitude fibre thinning electrospinning
genuinely produces, eventually collapsing bead mass toward zero. This was
isolated to the radius/area reconstruction specifically: the interpolated
position field (and the element lengths it implies) shrinks only modestly
and non-monotonically over the same run, while stress and velocity only
show large excursions in the single event immediately preceding a failure,
consistent with a late consequence of the near-zero mass (via $F=ma$) rather
than an independent defect of their own interpolation.

Five defenses were added to the cross-section fit, none of which alone has
eliminated the failure on the long run that exposed it, each validated
against Tests 21--23 with zero regression. First, the fit is performed on
$\ln\left(\pi a_{i}^{2}\right)$ rather than the raw radius or area: the
reconstructed volume is linear in area but quadratic in radius, so fitting
area removes one amplification of any interpolation error, and fitting its
logarithm additionally guarantees a strictly positive recovered value by
construction -- a raw area fit was observed to undershoot past zero -- while
linearising the roughly exponential thinning trend, which is far better
conditioned for the Akima tangent estimate than the area's own steeper
curvature. Second, an isolated single-event interpolation spike is removed
by a three-point median filter over the fitted target segment, excluding
anchor points, which must remain exact. Third, each non-anchor target point
is clamped to the range spanned by its two immediate bracketing source
points before the event, a local approximation of the shape-preserving
interpolation guarantee classic Akima does not provide; this was confirmed
unable, alone, to catch a drift already compounded through earlier events,
since that drift is by then baked into the ``legitimate'' source data too.
Fourth, interior points are instead bounded between their two bracketing
\emph{anchor} beads, with a generous margin, since anchors are restored
exactly at every event; this was found insufficient in isolation because an
anchor can itself already be tagged from an already-degraded bead -- anchors
are frozen at tagging time, not validated against anything. Fifth, the
Akima knot tangents for this field are limited to satisfy the classic
Fritsch--Carlson sufficient condition for a monotone cubic Hermite
interpolant, applied only to the cross-section and density fields (never
position, velocity, or stress, which may have genuine local extrema); this
delayed the failure the most of any single change tried, but the
compounding drift still eventually recurs across enough events, possibly a
cumulative resampling effect distinct from classic Akima overshoot and not
yet isolated. A sixth, absolute-floor variant of the evlim water-filling
(default 1~nm) is also present but was found too permissive to engage on
this input, since electrospinning legitimately reaches sub-micron fibre
radii; it remains as a defense against a genuine sign crossing the other
layers might miss.

The practical driver of the compounding drift on this specific long run
turned out to be its refinement \emph{cadence}, not a defect the five
interpolation-side defenses above could fully absorb. The run combined a
tight threshold ($0.10$~cm, five times the base resolution) with a short
minimum interval between accepted events ($10^{-5}$~s), so growing the jet
from a single nozzle bead accumulated several dozen accepted refinement
events -- each re-fitting the cross-section from the previous event's own
output -- within under $2\times10^{5}$ timesteps. Reusing Example 5's
established, coarser cadence instead ($0.4$~cm threshold, i.e. twenty times
the resolution, and a $10^{-3}$~s minimum interval) let the same input run
past $6.5\times10^{7}$ of its $10^{8}$ timesteps (324 accepted events)
without incident: the minimum bead radius measured at each event stayed
constant at its initial value across the entire run, and the active-bead
count settled into the stationary insertion/removal oscillation the case
was designed to reach. This is now the cadence shipped with that example
input. A corresponding advisory, warning 108, is issued whenever the
configured or auto-derived \uline{dynam refin threshold} is set below
twenty times the discretization resolution; it does not change behaviour,
since the historical Example 5 and Tests 21--23 references themselves use
values below that recommendation and remain validated short-window cases,
but it flags the combination that produced this failure mode for any input
exercising many consecutive refinement events over a long integration
window.

This investigation itself targeted the serial GFortran path only, and
fitting $\ln\left(\pi a_{i}^{2}\right)$ and the three
despiking/local-source/anchor-envelope steps already applied on the
OpenACC path from the start, since they wrap the fit regardless of which
backend performs it. The evlim floor, the radius floor, and the
Fritsch--Carlson monotonicity limiter have since been ported to their
OpenACC counterparts as well: the two water-filling floors are applied by
bringing just the small accepted-event segment to the host, calling the
identical, already-validated host subroutine, and returning the corrected
values to the device -- an exact reuse, not a reimplementation, since this
correction is rare, small, and inherently sequential, the same rationale
already applied elsewhere in this port to the normalized target-mesh
construction. The monotonicity limiter was ported natively into the
device Akima kernel's own tangent computation, using the same single-thread
device region that kernel already uses for its endpoint-slope
extrapolation. Validated on a native NVIDIA A30: Tests 21--23 pass on all
five available comparison backends, including a device-versus-host Akima
coefficient/value comparison at the same roundoff level as the
pre-existing documented baseline, and a GPU run of the real
\texttt{examples/input-24} ran past 2.5 million steps (12 accepted
refinement events) with no error and no recurrence of the evlim/$c_p$
blowup.
