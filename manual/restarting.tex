\section{Restarting JETSPIN\label{sec:Restarting-JETSPIN}}

A simulation can be restarted after normal termination or after it was
stopped by its time limit (the directives \textit{job time} and
\textit{close time}, measured as elapsed wall-clock time; see Section
\ref{sec:Input-file}). In order to restart
a JETSPIN job the file \texttt{input.dat} is again required together
with the file \texttt{restart.dat}, which is the exact copy of the
\texttt{save.dat} file created by the previous job. In particular,
the \texttt{save.dat} file was written by JETSPIN every
\texttt{restart dump} steps (100,000 by default) and at the end of the
previous simulation. The file \texttt{save.dat}
is \textit{not} human readable, and it should be renamed as \texttt{restart.dat},
and located in the same directory of input file. If the user attempts
to restart JETSPIN without the \texttt{restart.dat} file, the job
will immediately exit with error. Note that the directive ``\textit{restart
yes}'' needs to be added in input file in order to restart a previous
JETSPIN job (see Section \ref{sec:Input-file}); the directive
``\textit{restart reset}'' is still accepted but has no effect (see below).
It is worth stressing that JETSPIN will append new data to the files
\texttt{statout.dat} and \texttt{traj.xyz} (and to the developer binaries
\texttt{statdat.dat}, \texttt{traj.dat} and \texttt{bead.dat}, if
enabled), creating them if they are missing, while all the other output
files will be \textbf{overwritten} (included the \texttt{save.dat} file). Thus, the user is advised to keep backup
copies of the \texttt{restart.dat} file, noting the times it was written,
to help you avoid going right back to the start of a simulation.

The same restarting procedure can be also used for extending a simulation
beyond its initial duration. The restarted job resumes from the step and
time stored in \texttt{restart.dat} and integrates up to the value of the
directive \texttt{final time}, which should therefore be increased to the new
total simulated time. For instance, if a simulation run with
``\textit{final time 1.d-3}'' needs to be extended by a further
$5\times10^{-4}$ seconds, the user should set ``\textit{final time 1.5d-3}''
and include the ``\textit{restart yes}'' directive, leaving
\texttt{timestep} unchanged. Note that there is no directive for the number
of steps: since directives are matched by the leading characters of each
word, a record such as ``\textit{timesteps 15000}'' would be read as
``\textit{timestep 15000}'' and would set the integration step to 15000
seconds. Further,
the restarting procedure can be useful in the event of machine failure.
Here, the job can be restarted in the same way from the \texttt{save.dat}
file, which is written every \textit{restart dump} steps in order to meet
just such an emergency. We stress that the procedure is not foolproof
in the last event, since the job could be crash while the \texttt{save.dat}
file is being written.

Since version 2.0 the restart file stores the bead state in double
precision, followed by the state of the run that the beads do not carry: the
position in the pre-generated Gaussian pool (Sec.~\ref{sec:Noise-pool}) and
the number of times it has been read through, the state of the
random-number generator, the counters of the dynamic refinement and of the
anchor tagging, and whether the device step of the OpenACC build has engaged.
This block carries a version number (currently 2); a file of an earlier
version, written by development builds, restarts with the device gate
closed. If the saved state of the random-number generator has a size
different from this executable's (as with another compiler), it is not
restored and a warning is printed.
With the same \texttt{input.dat} and the same executable, a restarted
simulation therefore continues the uninterrupted one exactly, with or without
evaporation; the script \texttt{tests/restart/run.sh} checks this for Tests
12, 13, 16, 17, 24 and 25 and Examples 4 and 8. The statistics accumulated since the last print are not
restored, so that every printed row is reproduced when the restart interval
is a multiple of the print interval; the directive ``\textit{restart reset}''
has no further effect. Restart files written by JETSPIN 1.22 or earlier
are still read, in single precision and without the state of the run, so
that the random sequence restarts from the beginning; those versions could
not restart a simulation with evaporation.
